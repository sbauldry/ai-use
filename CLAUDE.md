# AI Use in the Graduate Program in Sociology (Purdue)

## Purpose
Two surveys documenting AI/LLM use (ChatGPT, Claude, Gemini, etc.) in our department:
one of **graduate students** (Qualtrics) and one of **faculty** (to be added).
Results will (1) guide department policy and support, and (2) inform the dean.
Context: the university wants to *promote* AI use and integrate it into teaching,
training, and work, so reports should describe actual practice, needs, and concerns
neutrally and not presuppose that more use is better or worse.

## Deliverables
- One report for graduate students and one for faculty (`reports/grad/`, `reports/faculty/`).
- Work order: graduate students first; faculty survey and data to be added later.

## Graduate student survey (n = 19 of 31 invited, ~61% response rate)
Instrument: `instruments/grad_survey.docx`. Anonymous Qualtrics survey, responses recorded 2026-09-30 to 2026-10-07.
Questions (Qualtrics variable names):
- `Q2_1`–`Q2_15`: frequency of AI use in **coursework** over past year
  (Never / Sometimes / Regularly / N/A) for 15 tasks: summarize readings, understand
  readings, explain concepts, search literature, synthesize literature, brainstorm,
  outline, first draft, feedback on draft, revise, edit for grammar/style,
  write/debug code, inform modeling strategy, interpret statistical results, analyze
  qualitative data. Items run in docx order (`Q2_1` = first listed, ... `Q2_15`).
  The numbers in parentheses in the docx are Qualtrics choice IDs, not column suffixes.
- `Q3`: open-ended, how/when they decide to use or not use AI in coursework.
- `Q5_1`–`Q5_13`: use/plan to use AI for **AP or dissertation** (Yes / No / N/A) for 13 tasks. Note the task order differs from Q2 (e.g., `Q5_10` = modeling strategy, `Q5_11` = code), so match on question text in CSV row 2, not on suffix.
- `Q4`: open-ended, how/when they decide to use or not use AI for AP/dissertation.
- `Q6`: open-ended, other comments.
- `Q7`–`Q12` in the docx are a duplicate of Q2–Q6 (second survey block / copy); all are
  empty in the data and are dropped.

Qualtrics CSV layout: row 1 = variable names, row 2 = question text, row 3 = ImportId JSON,
rows 4+ = responses. Value labels are text (e.g., "Never"), not codes.
Not every respondent answered every item (item n varies, ~13–18); always report the
denominator and don't treat missing as "No". "N/A" is a substantive answer distinct from missing.

## Data and privacy
- GitHub repo is **PUBLIC** (github.com/sbauldry/ai-use). User approved pushing data, code, and outputs.
- The survey is described to respondents as *anonymous*, yet the raw Qualtrics export has IP
  addresses and geolocation. So `data/raw/` is **gitignored (local only)**, and
  `code/01_deidentify_grad.R` produces `data/deidentified/grad_ai_use.csv`, which is the
  committed file and the one all analysis reads. Never commit anything from `data/raw/`.
  Manual redactions of identifying details in open-ended text (Q3/Q4/Q6) are applied by that script from
  `data/raw/redactions_grad.csv` (also local only, because it quotes the original text). Any quote used in a
  report must come from the redacted file.
- With only 19 respondents in a small program, open-ended text can be identifying (specific
  courses, advisors, cohort, nationality, etc.). Before quoting in a report or committing
  text outputs, review quotes for identifiability and lightly redact. Do not report cells
  for subgroups with very small n; no subgroup breakdowns are possible beyond the items asked
  (no demographics or year-in-program were collected).
- Faculty data will be even more identifiable (small department); apply the same
  de-identification approach and check with the user before committing it.

## Conventions
- R (tidyverse, ggplot2, knitr, rmarkdown installed; quarto, pandoc, officer, flextable
  are **not** installed). Python 3 exists without docx/pandas. Scripts run from the project root
  with `Rscript code/<name>.R` and use relative paths.
- Scripts are numbered in run order (`01_...`); faculty scripts get a `_faculty` suffix.
- Outputs are regenerated by code, never hand-edited.
- Report in plain language for a mixed audience (department + dean); small-n caveats
  (counts alongside percentages, e.g., "11 of 18") rather than percentages alone.
- Figures: consistent ordered categories (Never < Sometimes < Regularly), colorblind-safe palette.
- Commit/push only when asked.
